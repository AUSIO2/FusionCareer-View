# 岗位批量导入接口约定

前端页面和 Excel 模板以平台岗位字段为主，学院历史大/小实习表仅作为兼容参考。接口路径集中定义在 `src/lib/jobImport.mjs`。

## 请求

- 方法：`POST /admin/job-post/import`
- 类型：`multipart/form-data`
- 文件字段：`file`
- 支持格式：`.xlsx`、`.xls`
- 前端限制：最大 10 MB

## 工作簿识别

优先解析名为 `岗位数据` 的工作表。第 1 行为固定表头，第 2 行起每行代表一个岗位；空白行忽略。`填写说明` 不参与导入。

新模板必填字段为：`单位名称`、`岗位名称`、`岗位职责`、`招聘类型`、`岗位大类`、`薪资是否公开`。其余字段允许留空并在草稿箱中补充。`薪资是否公开` 即使选择“否”也必须明确填写。

如不存在 `岗位数据` 工作表，应兼容学院历史表：

- 第 2 行为表头的 12 列、15 列或 16 列格式。
- 关键列为“单位名称/公司名称”、“实习岗位”、“需求人数”。
- 单位、部门等因合并单元格产生的空白值，先向下填充再解析。
- 第 3 行如为填写示例则跳过。
- 联系人、联系电话和“不对外”备注不写入公开岗位。

## 字段规则

- `单位名称` → `companyName`，`所属部门/业务线` → `department`，`岗位名称` → `positionName`。
- `招聘人数` 只接受单一正整数并写入 `headcount`；人数未定时留空。
- `岗位职责` → `jobDesc`，`招聘类型` → `recruitType`，`工作形式` → `workMode`，`详细工作地点` → `workLocation`。
- 日期、省市、每周天数和实习时长等结构化列直接写入对应岗位字段。
- `专业要求`、`毕业年份要求`、`技能要求`、`其他要求` 分别写入独立字段。
- `官网投递链接` 为空时按平台内投递处理；不为空时写入 `sourceUrl` 并按外部链接投递处理。

历史表中的 `招聘要求`、`实习时间及频次要求`、`职场发展方向` 保留原文，分别加前缀后合并到 `reqOther`。历史表缺少岗位大类时，允许暂存 `OTHER`，并通过 `warnings` 提示管理员复核。

## 薪资隐私规则

- 历史表中的 `薪资/补贴说明` 或 `薪资/补贴说明（不对外）` 只供管理员核对，不写入公开薪资字段。
- 只有 `薪资是否公开` 明确为“是”时，才处理公开薪资列。
- `薪资下限`、`薪资上限` 用于结构化筛选；`薪资展示文字` 用于“面议”、补贴说明或自定义展示文案，填写后优先展示。
- 如选择“否”，即使公开薪资列有值，也应忽略并返回提醒；如选择“是”，三项公开薪资中应至少填写一项。

## 保存与响应

- 每条成功解析的岗位均以 `OFFLINE` 状态保存，进入草稿箱，不直接发布。
- 允许部分成功：不合法行通过 `errors` 返回，可修正但需复核的行通过 `warnings` 返回。
- 推荐返回 `successCount`、`failedCount`、`errors` 和 `warnings`。前端同时兼容 `importedCount`、`createdCount`、`failureCount`、`failedRows` 和 `warningMessages`。
